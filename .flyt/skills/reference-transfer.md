# Reference transfer

Use this when turning a reference repository into guidance for this project.

- Separate observed mechanism, local relevance, and proposed adaptation. Never
  present an adaptation as behavior that already exists here.
- Cite the full `reference:<name>/<path>:<line>` for every transferred claim.
  If the exact line was not opened, mark the claim unverified and do not use it
  to justify queued work.
- Classify each finding as: native fit, requires a Flyt product extension, or
  foreign-harness detail that should not transfer.
- Preserve disagreements between independent readers when the evidence does
  not settle them. Do not turn consensus-by-repetition into certainty.
- Prefer one reusable mechanism with a clear boundary over a catalog of copied
  conventions.

Flyt skills contribute instructions only. They never grant tools, create hidden
dependencies, or bypass approval, evidence, and Loop gates.
